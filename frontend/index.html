The Problem

Large video uploads shouldn't hold your API hostage.

Traditional web applications slow down, freeze, or time out when users upload large video files. Processing, transcoding, and distributing high-definition video in real time strains servers and ruins user experience. StreamForge solves this by decoupling the upload process from the transcoding engine — your users get an instant response while our system does the heavy lifting behind the scenes.

// without streamforge POST /videos/upload
  → transcoding inline...
  → request blocked 00:47
  → client timeout
  → 504 Gateway Timeout
// with streamforge POST /videos/upload
  → stored to MinIO (0.3s)
  → 202 Accepted
  → status: PROCESSING
  → status: READY (background)
Core Capabilities

Everything the pipeline needs, nothing your API should carry.

Instant Asynchronous Ingestion

Raw videos are written directly to high-performance object storage (MinIO/S3 compatible), immediately releasing the client connection.

→ Zero request timeouts. Zero waiting for users.

Adaptive Bitrate Transcoding

Sources are automatically processed into HLS formats — 1080p, 720p, and 480p streams — wrapped in a master .m3u8 playlist.

→ Seamless playback, dynamic quality switching.

Automated Thumbnail & Media Extraction

Leveraging FFmpeg/FFprobe, the platform grabs a high-resolution preview poster and extracts deep audio/video codec metadata.

→ Rich previews ready the moment a feed loads.

Enterprise-Grade Security

Secure endpoint protection using stateless JSON Web Tokens (JWT) and strict resource authorization rules.

→ Creators only ever manage their own content.
The Workflow

How the magic happens.

01

Upload

A user uploads a video file via the secure Spring Boot API.

02

Stage

The raw video is saved to MinIO object storage, and metadata is registered in PostgreSQL.

03

Queue

A messaging event is dispatched to RabbitMQ, notifying the processing queue.

04

Transcode

Background workers consume the message, spin up FFmpeg, transcode into HLS streams, generate thumbnails, and analyze codec data.

05

Publish

The final HLS assets are pushed back to storage, the database status updates to READY, and the video is instantly available for global streaming.
