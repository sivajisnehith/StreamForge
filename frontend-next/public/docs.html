StreamForge Developer Documentation

Welcome to the developer documentation for StreamForge. StreamForge is an enterprise-grade, asynchronous video ingestion and adaptive bitrate streaming (HLS) platform. It provides developers with endpoints to handle user authorization, seamless video uploads, metadata querying, and direct video streaming links.

Architecture Philosophy

Instead of transcoding uploaded videos synchronously within the HTTP thread (which causes client timeouts), StreamForge writes files immediately to storage and offloads heavy media transcoding tasks to background workers via RabbitMQ.

Architecture Overview

StreamForge consists of several key building blocks collaborating asynchronously:

Component Technology Role
API Gateway Spring Boot (Java 21) Exposes REST endpoints, validates payloads, enforces JWT security rules.
Message Queue RabbitMQ Coordinates and schedules transcoding events. Defers heavy loads.
Object Storage MinIO (S3-compatible) Stores raw uploads and generated multi-resolution HLS media segments.
Metadata DB PostgreSQL Persists creator accounts, video details, status tracks, and metrics.
Media Engine FFmpeg / FFprobe Transcodes inputs to HLS, extracts posters, and details codecs.

Quickstart

Getting the local development environment and application running takes just one step since the entire architecture is completely dockerized:

1. Spin up the entire Docker network

Build the StreamForge application container and start it alongside Postgres, RabbitMQ, and MinIO in a single command:

docker-compose up --build -d

This command builds the StreamForge image from the local Dockerfile, configures networking, and links all services automatically. The API will be available locally at http://localhost:8080. You can access the interactive Swagger API sandbox at http://localhost:8080/swagger-ui/index.html.

Authentication

All video ingestion and mutation endpoints require a JSON Web Token (JWT) sent via the Authorization header.

POST /api/auth/register

Register a new creator account.

curl -X POST http://localhost:8080/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username": "creator1", "password": "secure_password"}'
POST /api/auth/login

Authenticate credentials and retrieve a secure access token.

curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "creator1", "password": "secure_password"}'

Returns a JSON token payload:

{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}

Upload Video

Upload a raw media file for asynchronous HLS processing.

POST /api/videos/upload

Requires header: Authorization: Bearer <token> and Content-Type: multipart/form-data.

Request Parameters

Field Type Description
file Multipart File The raw video file (max 150MB by default). Mimetypes validated.
title String Video title (1 to 100 characters). Required.
description String Short description of video content. Optional. 
curl -X POST http://localhost:8080/api/videos/upload \
  -H "Authorization: Bearer eyJhbGciOi..." \
  -F "file=@demo_video.mp4" \
  -F "title=Introduction Video" \
  -F "description=Getting started guide"

Returns HTTP code 202 Accepted, indicating the ingestion started:

{
  "videoId": "8f3b23a1-7b0d-4ea3-8822-2a5490bc8201",
  "status": "PROCESSING",
  "message": "Video uploaded successfully. Transcoding started in the background."
}

List Videos

Retrieve a paginated list of uploaded video records.

GET /api/videos

Query Parameters

Parameter Type Default Description
page Integer 0 Page number (0-indexed).
size Integer 10 Number of records per page.
search String null Case-insensitive title search keyword. 
curl http://localhost:8080/api/videos?page=0&size=5&search=intro

Get Video Metadata

Retrieve details, processing state, and HLS streaming URL of a specific video record.

GET /api/videos/{id} 
curl http://localhost:8080/api/videos/8f3b23a1-7b0d-4ea3-8822-2a5490bc8201

Response payload:

{
  "id": "8f3b23a1-7b0d-4ea3-8822-2a5490bc8201",
  "title": "Introduction Video",
  "description": "Getting started guide",
  "status": "READY",
  "hlsUrl": "http://localhost:9000/originals/8f3b23a1.../master.m3u8",
  "thumbnailUrl": "http://localhost:9000/originals/8f3b23a1.../thumbnail.png",
  "duration": 12.4,
  "width": 1920,
  "height": 1080,
  "codec": "h264",
  "creator": "creator1"
}

Delete Video

Delete a video record, removing all related media assets and transcoded folders from MinIO.

DELETE /api/videos/{id}

Requires header: Authorization: Bearer <token>. Action is protected; only the original creator of the video can trigger its deletion.

curl -X DELETE http://localhost:8080/api/videos/8f3b23a1-7b0d-4ea3-8822-2a5490bc8201 \
  -H "Authorization: Bearer eyJhbGciOi..."

HLS Playback Integration

To stream the adaptive bitrate video in web applications, fetch the hlsUrl from the video metadata and load it inside an HLS-compatible player.

Standard HTML5 + Hls.js Example

Use Hls.js to support HLS streaming in browsers that do not have native HLS capabilities (like Chrome, Firefox, or Edge on Windows):

<video id="video" controls width="640" height="360"></video>
<script src="https://cdn.jsdelivr.net/npm/hls.js@latest"></script>
<script>
  const video = document.getElementById('video');
  const videoSrc = 'http://localhost:9000/originals/8f3b23a1-7b0d-4ea3-8822-2a5490bc8201/master.m3u8';
  
  if (Hls.isSupported()) {
    const hls = new Hls();
    hls.loadSource(videoSrc);
    hls.attachMedia(video);
  } else if (video.canPlayType('application/vnd.apple.mpegurl')) {
    // Native support (Safari / iOS)
    video.src = videoSrc;
  }
</script>
